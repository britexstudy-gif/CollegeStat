This supplement connects reviewed university information to exact catalogue IDs. It is displayed by `UniversityEnrichmentSections` in the university profile. It does not write to the hosted database.

The initial publication covers 17 identities, with 72 selected current programme links, 67 official resources, five scoped admissions notes, six scoped cost notes, 11 people, two public university story indexes, seven videos embedded on actual university pages and nine existing licensed campus photographs. This is selected coverage, not complete records for 17 universities. An admissions note is not a structured entry-requirement row, and a tuition note is not a complete cost table. TUIT and NUUz programme names remain unfilled where reviewed course-level evidence is missing. No private applicant or admitted-student records are collected.

The source review corrected the Toronto supplement from University of Trinity College to the distinct University of Toronto ID. It rejected a Turin admissions page describing the 2020/21 cycle, broken virtual-tour paths and empty or binary HTTP responses. Resource URLs are shown only after a successful substantive page receipt or an explicit primary-source browser review. The archive includes failed attempts, so an HTTP error is never mistaken for verification. Existing September biographical and photograph sources keep their original check dates.

The all-catalogue inventory lives in `data/review/university-enrichment-oct15/coverage-inventory.json`. It distinguishes historical IPEDS completion fields, publisher subject labels, official catalogue entries, reviewed offers, requirements, admissions cohort snapshots, first-party resource links, reviewed assets and the new supplemental fields. Gaps are explicit. Historical completion fields and ranking classifications do not become offered courses. An image-cache record does not establish a correct logo or a reusable image licence.

Reproduce the inventory with:

```sh
python3 scripts/ingestion/collect-university-enrichment.py
```

Repeat the original bounded collection with:

```sh
python3 scripts/ingestion/collect-university-enrichment.py --fetch --manifest data/review/university-enrichment-oct15/source-manifest.json
```

Collection writes receipts and candidates in the review directory. It does not publish them. `browser-source-reviews.json` documents primary-source reviews used where the collector was blocked or a page was generated by scripts. Each accepted source retains its URL, retrieval information and either a content hash or a browser review pointer. Video IDs must appear in the exact university’s source page; YouTube search results alone are insufficient. Images need an exact institution match, author, source, reuse permission and licence.

For a future OpenCode or Freebuff batch, follow the exported `UniversityEnrichment` type in `lib/university-enrichment.ts`. Use a JSON envelope `{ "schema_version": 1, "records": [...] }`. Each institution has `university_id`, exact `university_name`, `country_code`, `official_domain`, `checked_at` and these arrays: `resources`, `programmes`, `admissions`, `costs`, `people`, `student_stories`, `videos`, `gallery`. Unknown arrays stay empty. Each field must have `verification_status: "verified"` and `checked_at` only after a human or supervising agent reviews its primary evidence. Preserve monetary currency, period and population in the fact scope. Preserve institution founder and company founder roles separately. Programme names and current intake claims require different evidence.

Validate reviewed batches before any proposed merge:

```sh
node --import tsx scripts/ingestion/review-enrichment-batch.ts reviewed-batch.json
```

An optional `--output data/review/.../validated.json` saves the validated review artifact. The validator rejects unreviewed fields, unsafe URLs, sources belonging to another institution, duplicate IDs, mismatched names/countries and unsupported official domains. It does not grant publication approval or overwrite the live supplement. Review and merge into the published supplement explicitly, then rerun validation and the all-catalogue inventory.
