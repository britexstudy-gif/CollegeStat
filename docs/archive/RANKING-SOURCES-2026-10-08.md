# Ranking source review — 8 October 2026

This pass adds **zero ranking observations** and performs **no hosted database writes**. It extends the publisher directory from eight to nine identities by adding CWUR, adds explicit availability/edition/reuse metadata, and makes all nine visible in the landing-page catalogue. Four systems have installed CollegeStat data: QS, THE, ARWU and selected Leiden Open scientific-impact indicators. Publisher references are not installed ranking datasets.

The user's latest request reauthorizes primary-source ranking research. It does not authorize bypassing source restrictions, using similarly named sites as the same publisher, or claiming that an external link constitutes an imported table. Existing QS/THE/ARWU positions, ties, bands, edition years and URLs remain untouched.

## UI and integration changes

- The landing ranking section now shows nine distinct systems with four internal data actions and five external/source-reference actions. Labels separate installed tables, selected Leiden indicators and publisher references. It does not say that nine systems are installed.
- The existing official QS/THE/ARWU/CWTS identifying assets remain unchanged. External systems use ordinary typographic names, not invented official logos. ShanghaiRanking and CWTS marks retain a contrasting background in both themes.
- `lib/ranking-systems.ts` retains the existing `imported` field for compatible consumers and adds explicit availability, coverage, edition and reuse notes. Metadata alone grants no DB publication permission.
- Reuse the existing `ranking_providers`, `ranking_editions`, `ranking_entries` and indicator equivalents; no parallel ranking tables or new migrations are needed for this UI change.

Before any new licensed import, obtain exact source/provider identity and intended-use permission, choose immutable edition/scope/methodology keys, reconcile UUIDs conservatively, retain source/year/retrieval/evidence, stage privately, and verify preserved ties/bands and anonymous publication boundaries. Actual imported record counts must be reported separately from metadata and parser support.
